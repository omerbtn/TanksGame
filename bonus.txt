BONUSES
=========

This file documents the additional features implemented as part of the bonus section in the tank game assignment.

1. Support for key = value CLI syntax
We added support for arguments with spaces around the = sign, such as:
num_threads = 40
Our parser can handle flexible formats like:
key=value
key = value
key= value
key =value

This makes the program more user-friendly and robust to common shell input mistakes.
It required extra parsing logic to join and sanitize argument tokens.

This is eligible for bonus credit based on: https://moodle.tau.ac.il/mod/forum/discuss.php?d=106427

2. Elegant Shared Library Loader with Reference Counting
We implemented a SharedObjectManager singleton that handles dynamic .so loading with automatic memory management.
Shared libraries are loaded on demand using dlopen.
Internally tracked using std::shared_ptr<void>, ensuring the library remains open as long as it’s used.
Once no references remain, dlclose is called automatically to release the library.
Explicit unload(path) method is also available to force cleanup when safe.
This design prevents memory leaks and redundant loads while ensuring safe concurrent usage.

3. Efficient Thread Pool for Parallel Execution
Instead of manually creating and joining threads for each game, we implemented a thread pool.
Benefits over raw thread spawning:
- Resource reuse: Threads are reused, reducing system overhead and startup latency.
- Cleaner API: Tasks are submitted using enqueue, and results are returned via std::future.
- Scalable: Allows us to control concurrency level via a single num_threads setting.
- Safe and clean: Automatic thread management prevents leaks and reduces race condition risk.
This makes the simulation engine both faster and cleaner, especially for running large numbers of games in parallel.
